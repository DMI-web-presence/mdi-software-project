# MDI Software Website Structure

## Goal

Build a polished presentation website for MDI Software that introduces the brand, explains services, shows pricing, highlights previous work and experience, and converts visitors through a guided project brief form.

## Primary Navigation

- Home
- Services
- Pricing
- Projects
- Experience
- Start a Project

## Page Sections

### 1. Landing

- Brand-first hero for MDI Software.
- Short value proposition focused on custom websites, web apps, automation, and business tools.
- Primary action: start the guided project brief.
- Secondary action: view pricing or projects.
- Credibility metrics such as delivery speed, integration capability, and custom build focus.

### 2. Services

- Presentation websites.
- Business websites.
- Web applications and dashboards.
- Automation and third-party integrations.
- Maintenance, performance, and SEO basics.

### 3. Guided Project Brief

A multi-step form that helps clients clarify their requirements before contacting MDI Software.

Steps:

- Project type and goal.
- Visual direction, including AI images, client-owned images, stock images, or recommendation.
- Dominant color and design style.
- Required sections.
- Required features and integrations.
- Budget and timeline.
- Contact details.

The form should generate a recommendation summary before submission, including suggested package, style, complexity, and selected sections.

### 4. Pricing

Three clear starting packages:

- Starter Website.
- Business Website.
- Custom Software.

Each package should show:

- Starting price.
- Best-fit client type.
- Included deliverables.
- Timeline estimate.
- CTA to begin the brief.

### 5. Projects

Project cards showing selected work or representative project types.

Each card should include:

- Project name.
- Short description.
- Role.
- Technologies or capabilities.
- Result or business outcome.

### 6. Experience

A compact experience section presenting:

- Years of software work.
- Technical strengths.
- Client communication style.
- Delivery process.
- Relevant milestones.

### 7. Contact / Final CTA

- Reinforce the guided brief as the preferred contact path.
- Include direct contact availability later if needed.
- Keep the visitor focused on submitting a useful project request.

## Future Pages

- `/projects` for detailed case studies.
- `/services` for individual service detail pages.
- `/blog` for SEO and technical articles.
- `/privacy` for form privacy and consent details.
